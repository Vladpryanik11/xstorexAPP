# Передача проекта Xstore

Состояние на 2026-11-03. Репозиторий: https://github.com/Vladpryanik11/xstorexAPP, ветка `main`.

## Как начать в новой сессии

1. Склонировать репозиторий и открыть его папку в Claude Code. `CLAUDE.md` загрузится автоматически.
2. Если нужен разбор оригинала DDE Store, взять отчёты анализа из архива `iStore-analysis-reference.zip`. Его передают отдельно, в публичный репозиторий он не кладётся (см. «Материалы анализа»).
3. Стартовое сообщение для новой сессии:

> Это проект Xstore — нативное iOS-приложение. Прочитай CLAUDE.md и docs/HANDOFF.md. Приоритет: iOS-клиент, серверная подпись IPA и управление сертификатами. Проверь актуальное состояние кода и тесты. Не исключай функции из ТЗ. Код пока не меняй.

## Что сделано

### Документы
- `docs/SPEC.md` — ТЗ: решения, этапы 1–3, палитра, архитектура.
- `docs/API.md` — контракт API v1, включая уточнения, принятые при реализации.

### Бэкенд (`backend/`) — этап 1 готов
- Вход по коду активации (одноразовые коды, Bearer-токены, в БД хранится только хэш), профиль, sign-out.
- Витрина из «комнат» четырёх стилей, «Показать все», карточка, история версий, категории, RU/EN по `Accept-Language`.
- Живой каталог: монотонная ревизия, `/catalog/changes`, SSE `/catalog/stream`, ETag и 304.
- Поиск, подсказки, исправление раскладки, запросы приложений.
- Установка: грант → OTA-манифест → IPA с поддержкой Range. `PreSignedProvider`: IPA уже подписан владельцем.
- Состояние магазина, версия клиента (обязательное обновление), телеметрия, push-токен.
- Админ-API: приложения, загрузка билдов (bundle id и версия читаются из IPA), витрины, категории, коды, состояние магазина.
- Базовые тарифы `month`, `quarter`, `year` создаются при старте, поэтому на чистой базе можно сразу выпускать коды.
- Seed: 24 вымышленных приложения с PNG-иконками на своём энкодере. Запрещён при `NODE_ENV=production`.
- **Проверено:** typecheck, 82 из 82 тестов, ручной прогон сервера (вход, витрина, ETag, грант, манифест, Range, поиск, SSE). В CI Docker-образ запускается с PostgreSQL.

### iOS-клиент (`ios/`) — этап 1 готов
- Окна-шлюзы: вход, «Магазин закрыт», «Подписка закончилась» (в том числе по `403 account_inactive`).
- 5 вкладок: Сегодня, Игры, Приложения, Менеджер (заглушка), Поиск.
- Витрина на compositional layout, карточка, история версий, поиск, аккаунт, обновление клиента, баннер установки.
- Установка: грант → опрос → открытие `itms-services`; `grant_expired` → новый грант.
- Живой каталог (SSE со своим разбором строк), ETag-кэш в памяти, телеметрия.
- Палитра оригинала, своя иконка — монограмма «i». 180 ключей локализации EN и RU совпадают.
- **Проверено:** CI собирает и проходит тесты на macOS (run 41597398556). На реальном устройстве приложение не запускалось.

### Деплой (`deploy/`) — подготовлен, не выполнен
- Docker Compose: api + PostgreSQL 17 + Caddy 2 (Let's Encrypt, потоковая отдача SSE, лимит загрузки 2 ГБ).
- В продакшене сервер не стартует без `DATABASE_URL`, `ADMIN_TOKEN`, `GRANT_SECRET` и HTTPS-адреса `PUBLIC_BASE_URL`.
- Пошаговая инструкция: `deploy/README.md`.
- **Проверено:** CI валидирует конфиги Compose и Caddy, собирает образ, запускает его с PostgreSQL, выпускает код и активирует его (run 41598842155).

## Для продакшен-деплоя

1. **Домен** с A-записью на IP VPS. Пользователь готовит его сам.
2. **Способ деплоя**: пользователь разворачивает по `deploy/README.md` или даёт SSH-доступ. SSH-ключ добавляется в конфиг SSH на машине, пароли в чат не передаются.
3. После деплоя: поменять `ISTORE_API_BASE_URL` для Release в `ios/project.yml` на `https://<домен>`.
4. Для установки на реальный iPhone: действительная подпись IPA и подходящий provisioning profile (Ad Hoc — с UDID устройства), HTTPS. Сертификаты и профили должны быть настроены.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Бренд | Xstore, палитра из исходного проекта (`#0041DC → #3672E0 → #6AA2E3 → #92BDEF`); исходники пока содержат имя iStore |
| Функционал | Полный объём сценариев DDE Store: каталог сторонних IPA, серверная подпись, UDID, сертификаты, менеджер IPA, контроль целостности и защита от переподписи — обязательные задачи |
| Сборка iOS | Только CI на GitHub Actions (у пользователя Windows) |
| Бэкенд | Node.js + TypeScript, Fastify, Drizzle, PostgreSQL / PGlite |
| Хостинг | Свой VPS, Docker Compose, Caddy |
| Минимальная iOS | 15.0 (как у оригинала) |
| Swift | Режим 5 со `strict concurrency = targeted`; переход на Swift 6 — позже |

## Следующие шаги по приоритету

1. **Нативное iOS-приложение Xstore:** витрина, поиск, аккаунт, импорт сторонних и модифицированных IPA, менеджер установок и OTA-установка.
2. **Подпись IPA:** реализовать серверную подпись и переподпись, выбор сертификата, проверку entitlements и provisioning profile; `PreSignedProvider` оставить дополнительным режимом.
3. **Устройства и сертификаты:** UDID, управление профилями, безопасная передача материалов подписи авторизованным устройствам, технически доступная подпись на устройстве, контроль целостности и защита от переподписи.
4. **Менеджер iOS-приложения:** импорт IPA (Файлы, ссылки, MEGA, Google Drive, Dropbox), push, кэш, помощь и отзывы, языки, RTL.
5. **Деплой и испытания:** HTTPS, реальная подпись и проверка установки на физическом iPhone. Домен и VPS — для продакшена, не блокируют локальную разработку.
6. **Остальной функционал:** подписки на приложения, подарки, веб-оплата, white-label, настройка имени и иконки, расширенные карточки.
7. **Техдолг:** CI на Node 24, `npm audit`, Swift 6, S3-реализация `BlobStorage`.

## Известные ограничения

- iOS не сообщает приложению, что установка закончилась: через 45 с кнопка возвращается в исходное состояние. Кнопки «Открыть» для установленного приложения пока нет.
- Кэш каталога на клиенте только в памяти.
- Без `GRANT_SECRET` ссылки установки перестают работать после рестарта сервера (в продакшене переменная обязательна).
- SSE между несколькими инстансами работает через опрос журнала изменений (`CATALOG_POLL_MS`).
- Синтетические IPA из seed на устройство не встанут: они только для проверки пути установки.
