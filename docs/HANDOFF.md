# Передача проекта Xstore

Состояние на 2026-11-03. Репозиторий: https://github.com/Vladpryanik11/xstorexAPP, ветка `main`.

## Как начать в новой сессии

1. Склонировать репозиторий и открыть его папку в Claude Code. `CLAUDE.md` загрузится автоматически.
2. Если нужен разбор оригинала DDE Store, взять отчёты анализа из архива `iStore-analysis-reference.zip`. Его передают отдельно, в публичный репозиторий он не кладётся (см. «Материалы анализа»).
3. Стартовое сообщение для новой сессии:

> Это проект Xstore. Прочитай CLAUDE.md и docs/HANDOFF.md, проверь, что `cd backend && npm ci && npm test` проходит, и коротко скажи, на чём остановились и что следующее по плану. Код пока не меняй.

## Что сделано

### Документы
- `docs/SPEC.md` — ТЗ: решения, этапы 1–3, палитра, архитектура.
- `docs/API.md` — контракт API v1, включая уточнения, принятые при реализации.

### Бэкенд (`backend/`) — этап 1 готов
- Вход по коду активации (одноразовые коды, Bearer-токены, в БД хранится только хэш), профиль, sign-out.
- Витрина из «комнат» четырёх стилей, «Показать все», карточка, история версий, категории, RU/EN по `Accept-Language`.
- Живой каталог: монотонная ревизия, `/catalog/changes`, SSE `/catalog/stream`, ETag и 304.
- Поиск, подсказки, исправление раскладки, запросы приложений.
- Установка: грант → OTA-манифест → IPA с поддержкой Range. `PreSignedProvider`: IPA уже подписан владельцем.
- Состояние магазина, версия клиента (обязательное обновление), телеметрия, push-токен.
- Push через APNs (HTTP/2, токен провайдера ES256 из ключа `.p8`, без сторонних библиотек): подписчики получают уведомление, когда загружен билд с версией выше текущей. Мёртвые токены удаляются. Тестовая отправка — `POST /admin/v1/push/test`. Без ключа push выключен (раздел «Push» в API.md).
- Админ-API: приложения, загрузка билдов (bundle id и версия читаются из IPA), витрины, категории, коды, состояние магазина.
- Базовые тарифы `month`, `quarter`, `year` создаются при старте, поэтому на чистой базе можно сразу выпускать коды.
- Seed: 24 вымышленных приложения с PNG-иконками на своём энкодере. Запрещён при `NODE_ENV=production`.
- Заранее, из этапа 3: подписки на приложения (Follow) — статус, подписка, отписка, mute, список (раздел «Follows» в API.md).
- **Проверено:** typecheck, 102 из 102 тестов (APNs — против локального HTTP/2-сервера, с проверкой подписи JWT), ручной прогон сервера (вход, витрина, ETag, грант, манифест, Range, поиск, SSE). В CI Docker-образ запускается с PostgreSQL.

### iOS-клиент (`ios/`) — этап 1 готов
- Окна-шлюзы: вход, «Магазин закрыт», «Подписка закончилась» (в том числе по `403 account_inactive`).
- 5 вкладок: Сегодня, Игры, Приложения, Менеджер (заглушка), Поиск.
- Витрина на compositional layout, карточка, история версий, поиск, аккаунт, обновление клиента, баннер установки.
- Установка: грант → опрос → открытие `itms-services`; `grant_expired` → новый грант.
- Живой каталог (SSE со своим разбором строк), ETag-кэш в памяти, телеметрия.
- Заранее, из этапа 3: Follow — колокольчик в навбаре карточки (подписка, меню с уведомлениями и отпиской), экран «Отслеживаемые» в аккаунте (долгое нажатие — уведомления или отписка).
- Push: разрешение спрашивается после первой подписки на приложение, токен APNs уходит на сервер при запуске и после входа, нажатие на уведомление открывает карточку. Окружение APNs (`APS_ENVIRONMENT` в `project.yml`): Debug — development, Release — production.
- Палитра оригинала, своя иконка — монограмма «i». 191 ключ локализации EN и RU совпадают.
- **Проверено:** CI собирает и проходит тесты на macOS (run 41597398556). На реальном устройстве приложение не запускалось. Код Follow собран и протестирован в CI (run 41632906976, ветка `feat/follows-ios`). Код push собран и протестирован в CI (run 41636599480, ветка `feat/push`).

### Ревью кода (3 ноября 2026, ветка `fix/review`)
Полное ревью нашло 10 проблем, все исправлены с тестами:
- iOS: `401` на старый токен больше не стирает новый, выданный при повторной активации (`TokenStoring.clear(ifEqualTo:)`).
- Загрузка старого билда не откатывает версию в карточке и не вызывает повторный push. У новой версии без `notes` прежнее «Что нового» убирается, и в push не попадают заметки прошлой версии.
- SSE подписывается на шину до чтения ревизии: изменение между ними больше не теряется.
- iOS-поток каталога переподключается только с `since`: отставший `Last-Event-ID` вызывал повторы и лишние `reset`.
- Установка: отмена во время передачи в iOS больше не возвращает её в список; истёкший при подготовке грант запрашивается заново.
- IPA снятого с публикации приложения не отдаётся и по действующему гранту.
- Ошибки шины каталога пишутся в лог; ревизия каталога читается один раз на запрос.
- **Проверено:** typecheck и тесты бэкенда, проверка ключей локализации, бэкенд в CI (run 41659007467). iOS с этими правками и переименованием в Xstore собран и протестирован в CI на коммите `a47d3bb` (run 41666527163). Прогоны iOS на `fix/review` и `main` не стартовали: GitHub не выделил macOS-раннер. Гонку SSE тест не воспроизводит: проверено, что поток работает как раньше.

### Деплой (`deploy/`) — подготовлен, не выполнен
- Docker Compose: api + PostgreSQL 17 + Caddy 2 (Let's Encrypt, потоковая отдача SSE, лимит загрузки 2 ГБ).
- В продакшене сервер не стартует без `DATABASE_URL`, `ADMIN_TOKEN`, `GRANT_SECRET` и HTTPS-адреса `PUBLIC_BASE_URL`.
- APNs необязателен: `APNS_KEY_ID`, `APNS_TEAM_ID`, `APNS_KEY_BASE64` задаются все три или ни одного, иначе сервер не стартует.
- Пошаговая инструкция: `deploy/README.md`.
- **Проверено:** CI валидирует конфиги Compose и Caddy, собирает образ, запускает его с PostgreSQL, выпускает код и активирует его (run 41598842155).

## Ждёт пользователя

1. **Домен** с A-записью на IP VPS. Пользователь готовит его сам.
2. **Способ деплоя**: пользователь разворачивает по `deploy/README.md` или даёт SSH-доступ. SSH-ключ добавляется в конфиг SSH на машине, пароли в чат не передаются.
3. После деплоя: поменять `ISTORE_API_BASE_URL` для Release в `ios/project.yml` на `https://<домен>`.
4. Для установки на реальный iPhone: аккаунт Apple Developer пользователя, IPA приложений и самого Xstore, подписанные его сертификатом (Ad Hoc — с UDID устройств в профиле).
5. Для push: ключ APNs `.p8` в `deploy/.env` и capability Push Notifications у App ID `com.istore.app` (`deploy/README.md`, раздел «Push-уведомления»). Без capability профиль не подпишет сборку с entitlement `aps-environment`.

## Следующие шаги по приоритету

1. **Деплой** по готовности домена, проверка `https://<домен>/healthz`, первые коды активации.
2. **Release-адрес API** в iOS. Затем подпись и сборка IPA самого Xstore в CI: сертификат и профиль из GitHub Secrets.
3. **Этап 2** (SPEC.md §2):
   - Менеджер: импорт IPA из «Файлов», по ссылке, из MEGA, Google Drive, Dropbox, с валидацией (эталон проверок — отчёт 01 §8.4);
   - «Данные и хранилище»;
   - push: базовая доставка готова; осталось — категории и настройки уведомлений, NSE для картинок, объявления и «новые приложения»;
   - кэш каталога в Core Data (stale-while-revalidate);
   - отчёт о проблеме по встряске, помощь и отзывы;
   - смена языка в рантайме, RTL;
   - веб-админка поверх админ-API;
   - регистрация UDID через профиль конфигурации для Ad Hoc.
4. **Этап 3**:
   - подписки на приложения (Follow): готово, включая push об обновлениях;
   - подарки и приглашения с веб-оплатой: Stripe, Platega, Pally;
   - white-label брендинг;
   - смена имени и иконки при установке;
   - пейджер карточек.
5. **Техдолг**:
   - `actions/checkout@v4` и `upload-artifact@v4` → версии на Node 24;
   - `npm audit`: 4 moderate в esbuild внутри dev-зависимости drizzle-kit;
   - переход iOS на Swift 6;
   - S3-реализация `BlobStorage`.

## Известные ограничения

- iOS не сообщает приложению, что установка закончилась: через 45 с кнопка возвращается в исходное состояние. Кнопки «Открыть» для установленного приложения пока нет.
- Кэш каталога на клиенте только в памяти.
- Без `GRANT_SECRET` ссылки установки перестают работать после рестарта сервера (в продакшене переменная обязательна).
- SSE между несколькими инстансами работает через опрос журнала изменений (`CATALOG_POLL_MS`).
- Синтетические IPA из seed на устройство не встанут: они только для проверки пути установки.
- Очередь рассылки push живёт в памяти процесса: если сервер перезапустить сразу после загрузки билда, уведомление об этой версии не уйдёт.
- Если сборку Xstore подписали профилем другого окружения, чем `APS_ENVIRONMENT` (например, Release с development-профилем), APNs отклонит токен как `BadDeviceToken`, и сервер его удалит.
