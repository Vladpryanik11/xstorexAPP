# iStore — техническое задание

Версия 0.1, 2026-11-02.

iStore — магазин iOS-приложений по подписке, работающий вне App Store. Он повторяет продуктовую модель, UX, визуальный стиль и архитектуру DDE Store 2.1.0. Подробный разбор оригинала лежит в `../../analysis/` (01 — продукт и UX, 02 — API, 04 — архитектура); номера разделов ниже ссылаются на эти документы.

## 1. Принятые решения

| Вопрос | Решение |
|---|---|
| Бренд | **iStore**. Свой логотип, иконки и тексты. Палитра — как у оригинала (§3) |
| Каталог | Только **свои и лицензированные** приложения. Кнопок «Открыть в App Store», модифицированных сборок и инструментов наполнения каталога чужими IPA нет |
| Установка | OTA-манифест (`itms-services://`) с сервера iStore; IPA подписывает сервер сертификатом владельца магазина или загружает уже подписанным |
| Чего нет | Раздачи сертификатов на устройства, подписи на устройстве общим сертификатом, защиты от переподписи в стиле `res.pack` |
| iOS-клиент | Swift 6, программный UIKit, iOS 15.0+, iPhone и iPad, проект генерирует XcodeGen, сборка в GitHub Actions (macOS) |
| Бэкенд | Node.js 22 + TypeScript, Fastify, Drizzle ORM. PostgreSQL в продакшене, PGlite (Postgres в WASM) для разработки и тестов, S3-совместимое хранилище IPA (локальная папка в dev) |
| Языки | RU и EN с первого дня, ключи без захардкоженных строк. Остальные 8 языков оригинала — после MVP |

## 2. Состав продукта и этапы

Приоритеты взяты из 01 §2 и §9.

### Этап 1 — MVP
1. **Вход по коду активации.** Код выдаётся после оплаты или админом. Устройство получает Bearer-токен, токен лежит в Keychain. Шит «Аккаунт»: план, срок, «Продлить» (веб-оплата), «Выйти».
2. **Шлюзы-окна** поверх интерфейса: вход, «Подписка закончилась», «Магазин закрыт». Порядок и поведение — 01 §3.1 и §4.1.
3. **Таб-бар из 5 вкладок**: Сегодня, Игры, Приложения, Менеджер, Поиск. Навбар с аватаром аккаунта.
4. **Витрина**: один контроллер на три вкладки, серверные «комнаты». Стили: hero-карусель, полка стиля 1 (строки по 3 в колонке, горизонтальный пейджинг), полка стиля 2 (крупные карточки), чипы категорий. Экран «Показать все» с пагинацией. Pull-to-refresh, состояния загрузки, ошибки и пустоты.
5. **Карточка приложения**:
   - hero-шапка в цветах приложения (`tint_light` / `tint_dark` / `bg_color`), кнопка установки;
   - полоса статистики (рейтинг, возраст, размер, категория);
   - скриншоты, описание, «Что нового», информация, история версий, похожие.
6. **Установка**: кнопка с кольцом прогресса, стадии `preparing → ready → handing_off → installing`. Баннер активности над таб-баром. Проверка совместимости (`min_os`) и места до старта. Ошибки по схеме «что случилось + что сделать».
7. **Поиск**: результаты с пагинацией, подсказки, история, пустое состояние с «Запросить приложение».
8. **OTA-обновление самого клиента**: баннер, шит, обязательный режим.
9. **Телеметрия** установок и сетевых ошибок, журнал диагностики.
10. **Живой каталог**: SSE `/catalog/stream` + догрузка `/catalog/changes?since=`. Снятые приложения скрываются сразу.
11. **Админ-API** для наполнения каталога, комнат, кодов активации и состояния магазина. Seed-скрипт с демо-каталогом из вымышленных приложений.

### Этап 2 — v1.x
- Push (APNs) с категориями, Notification Service Extension для картинок, настройки уведомлений.
- «Данные и хранилище», кэш каталога в Core Data (stale-while-revalidate), ETag.
- Помощь и отзывы, отчёт о проблеме встряской (окно, скриншот, офлайн-очередь).
- Смена языка в рантайме, RTL.
- Веб-админка (CMS) поверх админ-API.
- Регистрация UDID через профиль конфигурации (стандартный OTA Profile Service Apple) для ad-hoc-дистрибуции своих приложений.
- Менеджер: импорт своих IPA из «Файлов» с валидацией (01 §8.4).

### Этап 3 — v2
- Подписки на приложения (Follow), подарки и приглашения (один дизайн-вариант), веб-оплата с возвратом через deeplink.
- White-label брендинг (`/account/branding`).
- Кастомизация имени и иконки при установке, пейджер карточек, карточки-ответы в поиске.
- Apple TV — только если появится tvOS-версия.

## 3. Визуальный стиль

Источник — 01 §7.
- **Бренд-градиент** (диагональ, сверху справа → снизу слева): `#0041DC` → `#3672E0` → `#6AA2E3` → `#92BDEF`.
- **Тёмный вариант** (иконка документа и тёмные поверхности бренда): `#18429D` → `#0D2353`.
- **OG-карточка ссылок**: `#0040C8` → `#6BB4FF`.
- **Акцент** (tint) по умолчанию `#0041DC`, в тёмной теме `#3672E0`; сервер может переопределить его (`brand_color` / `brand_color_dark`).
- **Карточки приложений** окрашиваются в цвета самого приложения, как в App Store.
- **Liquid Glass**: на iOS 26+ системный `UIGlassEffect`, ниже — `UIBlurEffect(.systemUltraThinMaterial)`. Прогрессивное размытие под навбаром.
- **Иконки** — SF Symbols. Светлая и тёмная темы, Dynamic Type, VoiceOver, хаптики.
- **Тон текстов**: коротко, дружелюбно, без канцелярита, ошибки объясняют причину и следующий шаг. Тексты пишем свои, оригинал не копируем.

## 4. Архитектура клиента

Схема повторяет оригинал (04 §3) с исправлениями из 04 §10.5:
- **Composition root**: `AppContainer` (зависимости по протоколам) → `FeatureFactory` → `AppFlowController` (роутер, gate-окна в отдельных `UIWindow`).
- **Слои**: `App / Core / Features / Shared`, фичи друг от друга не зависят.
- **Конкурентность**: `actor` для сети и I/O, `@MainActor` для UI, `AsyncStream` для обновлений.
- **Списки**: `UICollectionViewCompositionalLayout` + Diffable Data Source.
- **Чего не делаем**: приватные API, глобальную шину строковых `NotificationCenter`-имён, «тихий звук» как keep-alive, `NSAllowsArbitraryLoads`, бинарник с символами в релизе.

## 5. Архитектура бэкенда

- **Fastify-приложение**, модули по доменам: `auth`, `catalog`, `search`, `client`, `installs`, `admin`.
- **Монотонная ревизия каталога**: каждое изменение приложения или комнаты пишет запись в `catalog_changes` с новой ревизией. Её отдают `/catalog/changes` и SSE.
- **Токены** — случайные 32 байта, в БД хранится только SHA-256. Коды активации одноразовые.
- **IPA** лежат в хранилище (интерфейс `BlobStorage`: локальная папка / S3). Установка выдаёт короткоживущий грант с подписанным URL на манифест и IPA.
- **Подпись** — интерфейс `SigningProvider`. Этап 1: `PreSignedProvider` (IPA уже подписан владельцем). Этап 2: адаптер к CLI `zsign` для переподписи своих сборок своим сертификатом.

Контракт API — в [API.md](API.md).
